## 1. 92KeBi（`backend\app\core\` + `real\analyze_real.py`）

### 模块用途
`core\` 是可移植的「92 打板模式」规则引擎：`board.py` 盘面统计 → `phase.py` 情绪周期状态机 → `leaders.py` 龙头六维评分 → `pools.py` 补涨/切换股票池 → `signals.py` 买卖信号 → `risk.py` 仓位风控。`real\analyze_real.py` 是实盘编排层，把真实行情折算后复用同一套引擎，输出与 mock 同构的 view。

### 情绪周期阈值（精确数字）
阈值表在 `config.py`，**双刻度设计**：mock（48 只小市场）用 `RULE`，实盘（全市场 5000+）用 `REAL_RULE`，`phase.set_rule()` 注入。

```python
RULE = {                       # mock，48 只
    "dt_decline_min": 6, "zt_boom_min": 9, "premium_probe_min": 2.0,
    "ladder_ascend_min": 5, "avg_pct_strong": 1.5,
}
REAL_RULE = {                  # 实盘，全市场
    "dt_decline_min": 80, "zt_boom_min": 60, "ladder_ascend_min": 5,
    "premium_probe_min": 1.5, "mean_strong": 0.5,
}
```

**状态机四相**：`main_decline`(主跌) → `probe`(试错) → `main_ascend`(主升) → `high_oscillate`(高位震荡)。

`_rel(x, thr)`：`x<=thr` 时返回 `x/thr`；超出时 `min(1.0, 0.6+0.4*min(1,(x-thr)/thr))`。

**主跌证据 `_e_decline`**（上限 1.2）：`dt_count>=thr` → `+0.6+0.35*_rel`；前日 `dt_count>=thr` → `+0.45`；`premium_end<=0` → `+0.3`；`mean_pct<=-1.2` → `+0.3`；`dragon_broken and premium_end<=-0.8` → `+0.3`；`dt_count>=thr*0.4 and mean_pct<=-1.8` → `+0.45`。

**主升证据 `_e_ascend`**：`zt>=zt_boom_min` → `+0.6+0.35*_rel`，`elif zt>=zt_boom_min*0.45` → `+0.25`；`max_streak>=ladder_ascend_min` → `+0.45+0.3*_rel`，`elif >= max(2,thr-2)` → `+0.15`；`premium_end>=1.5` → `+0.3`；`mean_pct>=mean_strong` → `+0.25`；**扣分**：`dt>=thr*0.5` → `-0.7`，`dt>=thr*0.8` → `-0.4`。

**`classify_day` 判定顺序**（逐条）：
1. `hard_decline = dt_count>=thr and 前日 dt_count>=thr` 或 `de>=1.0` → `main_decline`
2. 冷启动（无前值）：`zt>=zt_boom_min and max_streak>=ladder_ascend_min` → `main_ascend`；`dt>=thr` → `main_decline`；`zt>=1` → `probe`；否则 `main_decline`
3. 前值 `main_decline` → 默认 `probe`；若 `ae>=1.3 and max_streak>=ladder_ascend_min and dt<=thr*0.25` → 直接 `main_ascend`（强修复）
4. 前值 `main_ascend`/`high_oscillate`：`ae>=1.15` → `main_ascend`，否则 `high_oscillate`
5. 前值 `probe`：`ae>=1.0` → `main_ascend`，否则 `probe`

**置信度**（=前端温度计数值）：`main_decline` = `min(0.96, 0.72+_rel(dt,thr)*0.2 + (0.1 if premium_end<0))`；`main_ascend` = `min(0.96, 0.6+_rel(zt,zt_boom_min)*0.25+min(0.15,max_streak*0.02))`；`probe` = `min(0.94, 0.78 + 0.08(溢价≥1) + 0.06(涨停≥1))`；`high_oscillate` = `0.8-min(0.2,(ae-de)*0.2)`；最终 `round(max(0.45, min(0.97, conf)), 2)`。

**温度计**：`DashboardPage.jsx:70 gaugeOption(conf, color)` 的仪表值就是 `Math.round(conf*100)`，标注为「阶段置信度」。**它不是独立情绪温度**——92KeBi 没有第二套温度算法。

**盘面口径 `board.py`**：炸板 `limit_zone = high >= pre_close*1.095`，`explosion = exploded/attempts*100`；`dragon_broken`：前日 `streak>=4` 且今日未涨停且 `pct<=-3`；`mid_loss`：前日 2~3 连板且今日未涨停且 `pct<=-6.5`；`premium_end` = 昨日涨停股今日收盘涨跌幅均值；`premium_open` = 昨日涨停股今日开盘溢价均值。

**实盘口径 `real\market.py:531-570`**：溢价率与炸板在实时快照上重算，排除 `zt/dt/新股`；`explosion = exploded/attempts*100`（`high >= round(settlement*(1+rate),2)-1e-6` 为触及未封）。涨跌停幅度 `sina.limit_rate`：创业板/科创(300/301/302/303/688/689) `0.20`，北交所(4/8/92) `0.30`，主板 ST `0.05`，其余 `0.10`。

**仓位**：`PHASE_POSITION` → 主跌 `[0,10]%`、试错 `[0,20]%`、主升 `[70,100]%`、高位震荡 `[0,10]%`；`risk.PHASE_CAP` 内部系数 `0.10/0.20/0.90/0.10`。风控：单票 ≤25%、止损 -5%、永不加杠杆。

**评分权重**：龙头 `W={"L01":0.24,"L02":0.16,"L03":0.20,"L04":0.15,"L05":0.10,"L06":0.15}`，总分 ≥45 才认定总龙；补涨池权重 `0.15/0.20/0.18/0.19/0.13/0.15`，入池门槛 ≥50；切换池权重 `0.22/0.20/0.16/0.22/0.20`，入池门槛 ≥60。

### 企业微信推送（完整实现）
`ops.py` 的 `_wechat_push` 是**全仓最完整的推送实现**：多 webhook、字节级截断、errcode 判据、markdown 链接。

```python
def _wechat_push(text, page_url=None):
    hooks = _hooks()          # 环境变量 + data/wechat_webhook.txt + DB meta, 去重
    if not hooks:
        return {"sent": 0, "reason": "未配置微信 Webhook"}
    url = page_url or pub_url.ops_page_url()   # DB meta > WECHAT_PAGE_URL > 动态推导
    txt = str(text).strip()
    if url:
        content = f"{_clip_bytes(txt, 3600)}\n\n[📋 点击打开 92K 打板操作台]({url})"
        body = {"msgtype": "markdown", "markdown": {"content": content}}
    else:
        body = {"msgtype": "text", "text": {"content": _clip_bytes(txt, 1900)}}
    data = _j.dumps(body, ensure_ascii=False).encode("utf-8")
    sent, errs = 0, []
    for url in hooks:
        req = _ur.Request(url, data=data, headers={"Content-Type": "application/json"})
        resp = _ur.urlopen(req, timeout=6)
        j = _j.loads(resp.read().decode("utf-8", "ignore").strip() or "{}")
        if j.get("errcode") == 0:
            sent += 1                       # HTTP 200 不算成功, errcode==0 才算
        else:
            errs.append(f"errcode={j.get('errcode')} {j.get('errmsg')}")
    return {"sent": sent, "reason": "；".join(errs) if errs else None}
```

`_clip_bytes` 按 UTF-8 字节截断（markdown 3600B / text 1900B，中文 3 字节）。触发点：`sweep()` 每轮扫描（买点入买入池 `_notify_buy_change`、卖点结算 `_notify_sell_change`、人工移除/删除）。**重试：无**——单次 6s 超时，失败仅记日志。消息体示例：

```python
f"【92K 打板·买入池·持仓】{tag}\n{name}（{code}）{sector}\n"
f"买入价：{price} @ {when}\n信号：{signal}\n理由：{reason}"
```

### 定时任务（asyncio 自研，非 APScheduler）
`tasks\scheduler.py`：4 条受看门狗守护的循环 `poll/analysis/daily/mem`。
- `_real_poll_loop`：交易时段（工作日 9~16 点）间隔 `REAL_POLL_SECONDS=6`，其余 `600`；空快照强制 `30s` 重试
- `_analysis_loop`：`cadence = 6 (mock) / 12 (real)` 秒，重建视图后驱动 `ops.sweep`
- `_daily_loop`：每 `1800` 秒检查日期翻转，`_real_daily()` 在**北京时间 ≥15:00 且工作日**回填日 K
- `_watchdog_loop`：每 `30s` 检查循环存活，死亡即在 30s 内重建

- 交易窗口：`ops._in_window()` = 工作日 `09:25–14:59`

## 2. ReviewNotification（`app\report|llm|push|scheduler|datasources|web`）

### 模块用途
「复盘日报系统」：A 股交易日从东财/同花顺/新浪取真实行情 → 装配 M-US/M-GL/M-CN 模块 → LLM 只写文字（数字全部来自数据层）→ Jinja2 渲染 AntD 网页 → 企微推送 → 15 天清理。三份报告：美股收盘复盘、全球宏观早报、A 股收盘复盘。

### 温度计与复盘阈值（关键发现）
**「市场情绪温度计」不是规则打分，而是 LLM 给定的四档评级**。`specs.py`：

```python
RATINGS = ["极寒", "偏冷", "温和", "火热"]
```

`prompts.py` 把评级写进提示词约束（`"rating" 只能取 极寒/偏冷/温和/火热 之一`），`generator.py` 从 AI 的 JSON 中取出 `payload["rating"]`。**代码中不存在任何把数值映射到该四档的阈值函数**——因此没有可提取的数字边界。

温度计的**数据构成**来自两个 dataclass（`datasources\base.py`）：
- `Breadth`：上涨家数、下跌家数、平盘家数、`big_up`（≥+5%）、`big_down`（≤-5%）、合计
- `PoolStats`：涨停家数、跌停家数、炸板家数、**炸板率 = `broken/(broken+limit_up)*100`**、最高连板、连板梯队分布

`collectors.build_cn_report` 把两者塞进 `M-CN-02 市场情绪温度计`，连板梯队作为表格。美股同理但用 `breadth("us")`（东财 `fs=m:105,m:106,m:107`，按 `f3` **二分查找** 0/+5%/-5% 边界页，约 20 次请求替代全量 13800 只）。

**合规校验**（`validate_payload`）：模块缺失、缺风险提示、出现 `买入/卖出/建议加仓/建议减仓/目标价` 任一关键词即记问题。

### 企业微信推送（完整实现，含指数退避重试）
`push\wecom.py`。**注意：PRD 写的是「图文卡片消息」，实际实现是 `msgtype: markdown`，全项目无 `news` 图文消息体。**

```python
def build_markdown(payload, report_url) -> str:
    title = payload.get("title", "复盘报告")
    trade_date = payload.get("trade_date", "")
    summary = _summary_text(payload)          # max_len=180
    lines = [
        f"## {title}（{trade_date}）", summary, "",
        f"[点击查看完整复盘网页]({report_url})",
        f"<font color=\"comment\">如无法直接打开，请复制链接到浏览器</font>",
        f"<font color=\"comment\">{payload.get('risk_notice','')}</font>",
    ]
    return "\n".join(l for l in lines if l is not None)

def push_report(payload, report_url, report_id) -> PushResult:
    settings = get_settings()
    if push_already_succeeded(report_id, CHANNEL):   # 幂等: 同一报告只推一次
        return PushResult(ok=True, skipped=True)
    if not settings.wecom_webhook:
        return PushResult(ok=False, error="未配置企业微信群机器人 Webhook")
    body = {"msgtype": "markdown",
            "markdown": {"content": build_markdown(payload, report_url)}}
    retries = max(1, int(settings.push_retry_times))        # 默认 3
    for attempt in range(1, retries + 1):
        try:
            resp = httpx.post(settings.wecom_webhook, json=body, timeout=15)
            data = resp.json() if resp.content else {}
            if resp.status_code == 200 and data.get("errcode", 0) == 0:
                record_push(report_id, status="success", attempts=attempt, channel=CHANNEL)
                return PushResult(ok=True, attempts=attempt)
            last_error = f"HTTP {resp.status_code} errcode={data.get('errcode')} errmsg={data.get('errmsg')}"
        except Exception as exc:
            last_error = str(exc)
        if attempt < retries:
            time.sleep(min(2 ** attempt, 10))     # 退避 2s → 4s
    record_push(report_id, status="failed", attempts=retries, error=last_error, channel=CHANNEL)
    return PushResult(ok=False, attempts=retries, error=last_error)
```

摘要生成 `_summary_text`：优先 `conclusion`，否则取前 4 个 `status=="ok"` 且 `change_pct` 非空的指标拼 `标签 +x.xx%`；再前置 `赚钱效应：{rating}｜` 与 `风险偏好：{risk_on_off}｜`（后者仅全球早报）。推送链接由 `urls.report_url()` 动态拼装：`PUBLIC_BASE_URL` 优先，其次请求 Host，兜底 `http://127.0.0.1:{port}`；格式 `{base}/reports/{report_id}/`。Webhook 在设置页录入并密文存储（`security.mask_secret` 回显掩码）。

### 报告 HTML 模板（Jinja2 + JSON 内联 + React 渲染）
`report\render.py` 用 Jinja2 `Environment(FileSystemLoader(app/templates))` 渲染 `report.html`，把整份 payload 以 `window.__REPORT__ = {{ payload_json | safe }}` 内联（`</` 转义为 `<\/` 防 script 截断），前端 React + AntD（**本地 vendored，无公网 CDN**）读取该全局变量渲染。资源前缀固定 `../../static`，页面 URL `/reports/<id>/`。

### 定时任务（三档 + 清理，20 秒对齐）
`SCHEDULE = {"us": "09:00", "global": "09:20", "cn": "15:05"}`，`CLEANUP_TIME = "00:30"`。`runner.main` 常驻循环每 `20` 秒对齐一次 `hhmm == at`，当日每档只执行一次（`done` 集合 + reports 唯一键 + push_logs 三重幂等）。支持三种部署：常驻循环（systemd）、`cron`（`0 9 * * 1-5` 等逐字见 README）、`systemd timer`（`OnCalendar=Mon..Fri 09:00`）。交易日判定 `calendar.is_trading_day`：周末 → `data/holidays.json` 节假日 → 东财指数行情时间戳二次确认（取不到数据时不否决）。保留期 `retention_days=15`，过期删除站点目录并返回「已过期」页。

## 3. StockTradingReviewTool（`stockreview\` + `intraday_monitor\`）

### 模块用途
`stockreview\` 是 A 股每日复盘后端包（30 个模块）：`em.py` 东财抓取、`net.py` HTTP 封装、`analysis.py` 纯计算、`emotion_cycle.py` 情绪周期、`emotion_history.py` 情绪分、`review.py` 复盘总结、`realtime.py` 实时盘口、加 9 个策略扫描模块。`intraday_monitor\` 是独立进程（端口 8765）盘中监控，前端 `monitor.html` 单文件。

### 情绪分「温度计」（`emotion_history.py`，0~100，权重精确）
```python
def emotion_score(zt, zb, dt, breadth):
    zt_tc = zt["tc"] or len(zt["pool"]);  zb_tc = zb["tc"] or 0;  dt_tc = dt["tc"] or 0
    max_lb = max((int(x.get("lbc") or 0) for x in zt.get("pool") or []), default=0)
    jingjia = len([x for x in zt["pool"] if int(x.get("fbt") or 0) < 92600])   # 竞价涨停: 首封 <09:26:00
    zhaban_rate = round(zb_tc / (zt_tc + zb_tc) * 100, 1) if (zt_tc + zb_tc) else 0
    up_ratio = round(up / (up + down), 3) if (up + down) else 0.5
    score = round(
        min(zt_tc, 80) / 80 * 25            # 涨停家数, 80 家封顶
        + max(0.0, 1 - zhaban_rate / 50) * 20   # 炸板率, 分母 50
        + min(max_lb, 7) / 7 * 15           # 最高连板, 7 板封顶
        + min(jingjia, 10) / 10 * 10        # 竞价涨停, 10 家封顶
        + up_ratio * 20                     # 上涨占比
        + max(0.0, 1 - dt_tc / 30) * 10,    # 跌停, 分母 30
        1)
```
**等级**：`≥75 亢奋 / ≥60 活跃 / ≥40 中性 / ≥25 低迷 / else 冰点`。窗口 `DEFAULT_DAYS=15`，`_recent_trading_dates` 扫最近 **45 个日历日**，`tc>0` 视为交易日。

### 情绪周期五阶段（`emotion_cycle.py`，另一套整数打分）
`_score(m)` 逐条：涨停 `zt<30 → -2`；`≥150 +3`；`≥100 +2`；`≥60 +1`。炸板率 `>40 → -2`；`>30 -1`；`≤10 +2`；`≤15 +1`。连板 `≤2 → -2`；`=3 -1`；`≥7 +2`；`≥6 +1`。晋级率 `>50 +1`；`<15 -2`；`<30 -1`。大面 `≥30 -2`；`≥15 -1`；`≤5 +1`。跌停 `≥15 -1`；`≤3 +1`。量能环比 `≥+10% +1`；`≤-10% -1`。分值域 **-12 ~ +11**。

`_phase_of` 边界：龙头跌停且 `max_lb<=3` → **退潮**；龙头断板且炸板率 `>30` → **退潮**；`score>=6` **高潮**；`>=3` **发酵**；`>=0` **启动**；`score<0` 时若前值为高潮/发酵/退潮 且（炸板率 `>30` 或 大面 `≥15`）→ **退潮**，否则 **冰点**。

口径：晋级率 = 昨日涨停股今日 `pct>=limit_pct` 只数 / 昨日涨停数；**`limit_pct` 主板 9.8 / 创业科创 19.5 / 北交所 29.5**；大面 `big_loss_pct = -幅度*0.7` → **-7 / -14 / -21**；盘前/周末 `is_preopen = 时间<09:30 或 周末`。

### 复盘评级（`review.py`）
`_rating`：涨停 `≥100 +2`、`≥60 +1`；炸板率 `≤15 +1`、`≤25 0`、`≥40 -2`、否则 `-1`；`涨跌比≥2 +1`、`≤0.6 -1`；`最高连板≥7 +1`、`≤2 -1`；`跌停≥15 -1`。→ `score>=4 火热 / >=1 温和 / >=-2 偏冷 / else 极寒`。
`_stage_block` 阶段打分 `pos`：收盘≥MA20 `+1` 否则 `-1`；MA20 走高 `+1` 否则 `-1`；收盘≥MA60 `+1`；情绪等级冰点/低迷 `+1`；亢奋 `-1`；放量下跌 `-1`；权重护盘成长杀跌 `(sh_pct>=0.5 and cy_pct<-0.3)` `-1`。→ `≥3 反弹途中 / =2 震荡修复(偏多) / 1,0 震荡整理 / -1 震荡筑底 / else 弱势调整(情绪退潮)`。

### 数据源与抓取
纯 `urllib.request`（无 requests/aiohttp）。`net.http_get(url, timeout=18, tries=3)` 失败 `sleep(0.8)` 重试；`race_fns` 主备并发（东财优先，等待窗 0.8s）；`ttl_cache(15)` 函数级缓存（em.py 大面积使用）。URL：`push2delay/push2his.eastmoney.com/api/qt/{clist,ulist.np,stock/trends2,stock/kline,stock/fflow/daykline}/get`、`push2ex.eastmoney.com/getTopic{ZT,ZB,DT}Pool`、`web.ifzq.gtimg.cn/appstock/app/fqkline/get`、`quotes.sina.cn/.../getKLineData`、`dq.10jqka.com.cn/fuyao/hot_list_data/...`、`hq.sinajs.cn/list=`。历史接口连续失败 8 次熔断 300 秒。

### 推送
**不存在**。全项目（含 `.refactor_tmp\orig_server.py`、tests、static、README）grep `webhook|qyapi|wecom|企业微信|钉钉|server酱|pushplus|bark|telegram|msgtype|markdown|推送|通知` → **0 命中**；服务端只实现 `do_GET`，无 `do_POST`。项目内「推送」语义仅指前端轮询。

### 报告 HTML 与定时
**无模板引擎**：`server.py` 只输出 JSON，页面壳是静态 `static\index.html`（`<script type="module" src="js/main.js">`，24 个原生 ES module 用模板字符串 + `esc()` 拼 innerHTML）。「导出 HTML」是**浏览器端**行为（`review.js` `exportHtml()`：克隆 DOM + fetch CSS 内联 + `Blob` 下载 `A股大盘复盘_日期.html`）。
**无调度器**（无 APScheduler/cron/Timer）：只有 `SnapshotCache(ttl, fetcher)` 惰性刷新——30s（snapshot/realtime/ztpool/speedrank/sectormv/emotion_cycle）、60s（leaders/heatmap）、120s（volprice/pullback）、300s（hot）、600s（其余 14 个），加 `net.ttl_cache(15)`、`intraday_monitor` `CACHE_TTL=5`，以及启动预热线程 `_start_prewarm()`。

### 模块用途与语言

```js
var rec = Math.max(0, 100 - min * 0.15);        // 时间衰减 0.15 分/分钟
```

### 数据源与推送

推送为 **`msgtype: "text"` 纯文本（无 markdown）**，`drainPushQueue` 实现频控/去重/无上限重试：
```js
async function sendWecom(text) {
  if (!wecomWebhook) return { sent:false, reason:'未配置企微机器人 Webhook' };
  const r = await fet(wecomWebhook, { method:'POST',
    headers:{'Content-Type':'application/json'},
    body: JSON.stringify({ msgtype:'text', text:{ content:text } }) });
  const j = await r.json();
  return { sent: j.errcode === 0, reason: j.errmsg || '', errcode: j.errcode };
}
async function drainPushQueue() {
  while (PUSH.queue.length) {
    if (!wecomWebhook) { PUSH.enabled = false; return; }
    const now = Date.now();
    if (PUSH.sentTs.filter(ts => now - ts < 3600e3).length >= PUSH_POLICY.hourly) return; // 每小时上限 12
    if (now - PUSH.lastSent < PUSH_MIN_GAP) return;                                       // 20s 频控
    const it = PUSH.queue.shift();
    const key = hashKey(it.title) + ':' + Math.floor((it.ts || Date.now()) / 3600e3);
    if (PUSH.sentKeys.has(key)) continue;                    // 同标题+小时桶去重
    PUSH.sentKeys.add(key); if (PUSH.sentKeys.size > 300) PUSH.sentKeys.clear();
    const r = await sendWecom(wecomText(it));
    PUSH.lastSent = Date.now(); PUSH.sentTs.push(PUSH.lastSent);
    if (!r.sent) PUSH.queue.unshift(it);                     // 失败放回队首, 无次数上限
  }
}
```
消息模板：`【重要消息·财讯雷达】{title}\n类型：{type}｜来源：{source}\n时间：…\n关联：…\n点击查看详情：{SITE_URL}#n={id}\n原文：…\n（自动推送｜仅供参考，不构成投资建议）`。入队条件 `isAutoPushWorthy`：`imp` 且非传闻，且 `pushRelevant`（公告恒真 / 含美股美联储 → 推 / 纯外盘无 A 股信号 → 不推），且 `detectEvents` 命中默认开启的 6 类事件之一。

## 横向结论（可复用要点）

1. **推送最完整的两个实现**：`ReviewNotification\app\push\wecom.py`（markdown + 3 次指数退避 2s/4s + 幂等）与 `92KeBi\backend\app\ops.py::_wechat_push`（多 webhook + 字节截断 + errcode 判据 + markdown 深链）。四者共同点：**都以 `errcode == 0` 而非 HTTP 200 作为成功判据**。
2. **`msgtype` 实际情况**：4 个项目里 2 个用 markdown（ReviewNotification、92KeBi）、1 个用 text（FinancialNews）、1 个完全没有推送（MarketAlerts）。**没有任何项目实现企微 `news` 图文消息**，尽管 ReviewNotification 的 PRD 写的是「图文卡片消息」。
3. **两套真正可移植的情绪引擎**：`92KeBi\core\phase.py`（证据累加 + 四相 Markov 状态机，阈值按市场刻度双套）与 `StockTradingReviewTool\stockreview\emotion_history.py + emotion_cycle.py`（0~100 加权情绪分 + 整数打分五阶段）。后者的权重与边界数字最完整、最易直接复用。
4. **温度计有三种完全不同的语义**：92KeBi = 阶段置信度×100；StockTradingReviewTool = 0~100 加权情绪分；ReviewNotification = LLM 主观四档评级（无极值阈值）。统计口径不可混用。
5. **定时任务的三种形态**：自研 asyncio 守护循环（92KeBi）、20s 对齐 + cron/systemd timer 备选（ReviewNotification）、纯 `setInterval` 轮询（FinancialNews、MarketAlerts）；StockTradingReviewTool 完全没有调度器，只有 TTL 惰性缓存。
6. **任务清单中的两处路径/语言偏差**：`FinancialNews\server\` 无 Python 源码（仅 `server.js`/`package.json`/`cookies.json`）；`MarketAlerts\server\modules\` 存在但为 TypeScript 而非 Python。
