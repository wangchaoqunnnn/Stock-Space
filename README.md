# StockSpace · 股票决策平台

把工作区里 **11 个各自独立的股票研究项目**整合为一个可部署、可验证、可长期运行的单体平台。

* **数据底座统一**：16 项取数能力、多源容灾、单位与复权口径归一化
* **6 大业务能力**：趋势选股、潜涨雷达、涨停回调低吸、N 字战法、形态扫描、情绪周期
* **零构建前端**：原生 HTML/CSS/JS，无 CDN、无外链、无 npm，图表自研 Canvas
* **可观测**：内存监控、缓存明细、数据源健康度、定时任务、慢请求
* **企业微信推送**：信号 / 情绪 / 数据源异常 / 内存告警
* **一键部署**：Docker 与直接部署（systemd）两种方式，脚本自动选择

> ⚠️ **免责声明**：本平台是技术研究与学习工具，所有行情、评分、信号、回测与复盘结论
> 均为算法计算结果，**不构成任何投资建议**。历史表现不代表未来收益。

## 30 秒了解它是什么

| | |
|---|---|
| **它做什么** | 从全市场 A 股里按 5 套可调规则的策略筛出候选，给出评分与逐条依据；同时算市场情绪与周期阶段；支持回测验证与复盘报告；结果可推送到企业微信 |

## 快速开始

环境要求：**Python 3.10+**（推荐 3.12）。Docker 方式另外需要 Docker 20.10+。

### 方式一：一键部署（推荐，云服务器）

```bash
git clone <仓库地址> stock-space && cd stock-space
sudo bash deploy/deploy.sh
```

脚本会自动完成：环境检查 → 生成配置 → 建虚拟环境 → 装依赖 → 环境自检 →
注册 systemd 服务 → 放行防火墙端口 → 健康检查 → 打印访问地址。

脚本会**自动选择**部署方式：服务器上有可用的 Docker 就用 Docker，否则用直接部署。

```bash
sudo bash deploy/deploy.sh --mode docker          # 强制 Docker
sudo bash deploy/deploy.sh --mode direct          # 强制直接部署
sudo bash deploy/deploy.sh --port 9000            # 改端口
sudo bash deploy/deploy.sh --domain sa.example.com  # 顺便配 nginx
sudo bash deploy/deploy.sh --help
```

Windows 上（需要 Docker Desktop，或用本机 Python 直接跑）：

```powershell
pwsh -File deploy\deploy.ps1                      # 自动选择
pwsh -File deploy\deploy.ps1 -Mode direct -RegisterTask   # 直接部署并注册开机自启
```

> **别忘了云控制台安全组**：还要在云厂商控制台放行对应 TCP 端口，否则外网访问不了。

### 方式二：Docker Compose

```bash
cp .env.example .env        # 按需修改端口与配额
docker compose up -d --build
docker compose logs -f --tail=200
```

需要域名 / HTTPS / 子路径部署时启用 nginx profile：

```bash
# 先改 deploy/nginx.conf（或直接用它的子路径示例）
docker compose --profile with-nginx up -d
```

### 方式三：本地开发

```bash
# 后端（终端 1）
cd backend
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt    # Windows
# source .venv/bin/activate && pip install -r requirements.txt   # Linux/macOS
.venv\Scripts\python run.py --reload

# 浏览器打开 http://127.0.0.1:8770/
```

前端**无需构建**：直接改 `backend/stock_space/web/` 下的文件，刷新浏览器即可。

可选数据源（多两条独立取数通道，非必需）：

```bash
python -m pip install -r backend/requirements-optional.txt
```

安装后 AKShare / Ashare 会自动参与调度；不装也不影响其它功能（数据源页显示"未安装"）。

### 6 个策略一览

| 策略 | 一句话 | 最适合的行情 |
|---|---|---|
| **趋势狙击** | 均线多头 + 创阶段新高 + 回调低点抬高 + 温和放量 + 跑赢大盘，止损取「MA20×98% / 近10日低点×98% / 买入价-8%」最大值 | 指数在 MA20 上方的多头或震荡偏强 |
| **潜涨雷达** | 找"沿均线缓慢抬升、温和放量、低波动、还没被市场关注"的股票，五维加权评分 + 板块共振加分 | 震荡市与慢牛初期 |
| **涨停回调低吸** | 只做优质首板之后的**缩量回调企稳**，五信号（缩量/支撑/企稳/筑底/板块）必须全部通过 | 有规模化首板效应时 |
| **N 字战法** | 倍量点火 → 缩量回调 2~6 天不破点火低点 → B1 回踩低吸 / B2 放量突破，带大盘环境闸门 | 大盘 MA20 向上或横盘 |
| **形态扫描** | 16 套经典形态（均线突破/金叉/MACD/布林/枢轴/超卖反弹/地量放量/强势回踩/首板确认…） | 按形态各自适配 |
| **缩量回调后温和放量** | 心法「缩量回调是洗盘，放量下跌是出货」。强势股缩量回调（≤均量 70%）、跌幅收窄、守住 MA20 后，以第一根温和放量阳线进场；**回调期放量下跌一票否决**。风控：2×ATR 止损 / +16% 止盈 / +8% 后移动止盈 / 破 MA20 离场 / 12 日时间止损 | 强势股上升途中的正常洗盘 |

**每个策略的全部阈值都可以在页面调**，保存后立即生效；每个入选结果都能逐条展开
"哪一条通过、实测值是多少、阈值是什么"。策略清单由后端 `/api/strategies` 动态下发，
**新增策略不需要改前端**。

## 数据源

平台把取数需求收敛为 **16 项能力**，每项能力独立调度、独立熔断、独立排序。

| 数据源 | 覆盖能力 | 是否需要登录 | 说明 |
|---|---|---|---|
| **东方财富** | 快照/行情/指数/K线/分时/榜单/板块/资金流/涨停池/涨跌家数/代码表/人气/财报 | 否 | 覆盖最全的主源。主域名在部分网络被阻断时自动走 delay 镜像 |
| **新浪财经** | 快照/行情/K线/代码表/快讯 | 否 | 实时行情稳定；列表接口高频会被限流（自动冷却约 10 分钟） |
| **腾讯财经** | 行情/K线/分时/板块 | 否 | 批量实时行情字段最全（带量比与涨跌停价），一次可请求 60 只 |
| **同花顺** | K线/分时 | 否 | 按年份打包的历史日线，科创板与北交所也能取到 |
| **巨潮资讯** | 公告 | 否 | 交易所官方公告检索，返回标题与 PDF 原文链接 |
| **AKShare** | 快照/K线/板块/快讯 | 否（需安装） | 第三方聚合库，可选依赖 |
| **Ashare** | K线/行情 | 否（需安装） | 轻量单文件行情库，可选依赖 |
| **雪球** | 关注度/热帖 | **是** | 需要在页面粘贴 Cookie |
| **微博** | 热搜 | **是** | 需要粘贴 SUB/SUBP Cookie |

### 多源容灾怎么工作

1. **候选排序**：以你在配置里的顺序为主序（哪个源的字段更全就排前面），
   健康度只在同档内微调 —— 避免"快但字段残缺的源"把"稍慢但字段完整"的源挤掉；
2. **逐个尝试**：首个**通过校验**的结果即返回。校验很关键：免费源最常见的问题不是报错，
   而是**不报错但数据不全**（例如某个源对北交所只返回 1 根 K 线），这种情况会被判为失败并换源；
3. **熔断冷却**：连续失败的源进入冷却期，冷却期内直接跳过，不浪费超时等待；
4. **限流保护**：收到 456/429/403 时把该主机标记冷却，不再重试（避免越试越封）；
5. **真实切换有记录**：每次"主源→备源"都记录原因，在「数据源」页面可查看。

### 手动干预（都在「数据源」页面）

* **手动刷新数据** —— 清空缓存 + 复位熔断 + 重新拉取，返回实际生效的源与条数
* **手动切换源** —— 把某项能力锁定到指定源；留空恢复自动择优；**重启后依然生效**
* **连接性探测** —— 单个源或全部源，返回真实延迟与失败原因
* **手工录入上游地址** —— 按能力整体替换某源的 URL 列表（每行一个，第一个失败自动试下一个）；
  留空恢复内置地址。**代码里不写死任何域名**，所以你可以把它指向自建网关或代理
* **手工录入登录凭据** —— 需登录的源（雪球/微博）直接粘贴 Cookie；保存后会自动用真实请求验证；
  读取接口只回显掩码，绝不回显明文
* **模式切换** —— `auto`（推荐）/ `real`（只用真实数据）/ `synthetic`（内置合成行情，仅离线演示）

### 想看某个源在你这台机器上通不通

## 企业微信推送

### 配置

推荐在页面配置（会做掩码回显，也不会写进版本库）：

**用户配置 → 消息推送** → 填 Webhook → 保存 → 点「发送测试推送」

Webhook 获取方式：企业微信群 → 右上角 → 群机器人 → 添加 → 复制 Webhook 地址。

也可以先"先测再存"：直接粘贴 Webhook 点测试，验证通过再保存。

### 会推送什么

| 类型 | 触发时机 | 内容 |
|---|---|---|
| **定时推送** | `push.schedules` 配置的时刻（默认 09:00 / 11:35 / 15:05，北京时间） | 情绪分、周期阶段、涨跌家数、炸板率、最高连板 |
| **策略信号** | 定时任务发现**新增**入选标的时 | 策略名、新增只数、代码/名称/评分/通过的关键条件 |
| **数据源异常** | 某能力全部源失败时 | 失败源与原因，提示去数据源页处理 |
| **内存告警** | 触发内存护栏时（1 小时内最多一次） | 当前 RSS、阈值、已采取的动作 |

### 实现细节（这些是踩过坑之后定下来的）

* **以 `errcode == 0` 判定成功**，而不是 HTTP 200 —— 实测 HTTP 200 也可能带错误码；
* 失败按**指数退避重试**（2s → 4s，次数可配）；
* 按内容指纹**去重**，同一内容在去重窗口内只推一次，避免刷屏；
* 消息按 UTF-8 **字节安全截断**，不会把汉字切坏；
* 每次推送**写审计日志**，页面可查看成功/失败与错误码（常见错误码有中文解释）；
* 推送链接前缀默认按请求 Host 推导，**不写死域名**（也可以在配置页手动指定）。

## 配置

三层优先级（高 → 低）：

1. **环境变量** —— `SS_` 前缀，嵌套用**双下划线**，例如 `SS_SERVER__PORT=9000`
2. **运行期设置** —— 页面「用户配置」保存的内容，落在 `data/runtime_settings.json`（权限 600）
3. **配置文件** —— `config/app.toml`、`config/sources.toml`

所有配置都有内置默认值，`.env.example` 里**没有一项是必填的**。

### 常用配置

| 键 | 默认 | 说明 |
|---|---|---|
| `SS_SERVER__PORT` | 8770 | 监听端口 |
| `SS_DATA_SOURCES__MODE` | `auto` | `auto` / `real` / `synthetic` |
| `SS_QUOTAS__UNIVERSE_SIZE` | 0 | **0 = 全部 A 股**（约 5900 只）；小内存机器建议设 1500 |
| `SS_QUOTAS__SCAN_KLINE_BUDGET` | 1200 | 单轮扫描的日线请求上限（保护上游） |
| `SS_QUOTAS__KLINE_CONCURRENCY` | 16 | 日线并发（新浪反爬上限约 24） |
| `SS_QUOTAS__MEMORY_SOFT_LIMIT_MB` | 800 | 超软上限压缩缓存到 50% 并 GC |
| `SS_QUOTAS__MEMORY_HARD_LIMIT_MB` | 1400 | 超硬上限清空全部缓存 |
| `SS_SCHEDULER__TRADING_INTERVAL_SECONDS` | 30 | 交易时段刷新间隔 |
| `SS_SCHEDULER__DAILY_JOB_HOUR/MINUTE` | 15 / 10 | 每日任务（收盘后扫描+清理） |
| `SS_PUSH__ENABLED` | false | 推送总开关 |
| `SS_PUSH__SCHEDULES` | `09:00,11:35,15:05` | 定时推送时刻 |
| `SS_NEWS__RETENTION_DAYS` | 15 | 资讯保留天数 |

### 关于"不引用固定地址"

* **全项目第三方域名只出现在一个文件**：`config/sources.toml`；
* 它可被 `config/sources.local.toml`、环境变量（`SS_SOURCES__<源>__URLS__<能力>`）
  或页面「数据源 → 查看/编辑该能力地址」覆盖；
* 每个能力都是**候选地址列表**，天然具备换源能力；
* **前端零外链**：没有 CDN、没有外链字体/图片，图表是自研 Canvas；
* 前端资源与接口调用**全部使用相对路径**，可部署在站点根路径或任意子路径。

### 已经修掉的"看起来能用其实是坏的"缺陷（都有回归用例）

这些是整合过程中实测发现的，值得单独列出，因为它们都属于**静默失效**：

* 腾讯 K 线 bar 是 `[日期, 开, 收, 高, 低, 量]`，**不是 OHLC** —— 顺序写错会让最高/最低互换；
* 上游 JSONP 有**变量式包装**（`kline_day={...}`）—— 只按函数式 `cb({...})` 解析会让
  "HTTP 200 的正常接口"被误判为全部失败并整体换源；
* 东财快照的 `f14` 才是名称（`f13` 是市场号），且 `f100` 是行业 —— 字段错位会让
  全市场股票名称变空、板块共振与行业聚合整条链路失效；
* 指数与个股代码段重叠（`000001` 既是上证指数也是平安银行）—— 用股票快照匹配指数会把
  个股当指数显示；
* `await bound_method` **不会执行方法**，而是立刻返回方法对象本身且不报错 ——
  会让"可选数据块"永远拿到函数并被异常处理静默吞掉；
* 东财 `clist` 单页**硬上限 100 条**（`pz` 传多大都只给 100），需要约 60 页才能覆盖全市场；
* 设置深合并里**空字典不能表示"清空"** —— 会让"清除凭据""恢复内置地址"这两个按钮静默失效。

### 备份与恢复

```

# Docker
docker compose up -d --build
```

升级后建议打开 `/selfcheck` 点一次「全部重跑」。

### 内存调优

平台自带三层内存护栏：

1. 每个缓存都有**条目上限**，超限按最久未使用淘汰；
2. 条目带 **TTL**，读取与巡检时清理；
3. 进程 RSS 超**软上限**时把所有缓存压缩到 50% 并 GC，超**硬上限**时清空全部缓存。

容器部署时会自动读取 cgroup 上限并收紧阈值，避免被 OOM Killer 杀掉。

如果「内存监控」页面持续显示触发软上限，说明阈值或扫描范围不合理：

* 把 `quotas.universe_size` 设为一个有限值（如 1500），显著降低内存占用；
* 或调大 `memory_soft_limit_mb` / `memory_hard_limit_mb`；
* 或调小各缓存的条目上限。

## 常见问题排查

| 现象 | 原因与处理 |
|---|---|
| **页面能打开但数据全空** | 服务器访问不了行情上游。先跑 `python tools/probe_sources.py` 看哪些端点可达；再检查安全组出网策略与 DNS |
| **提示"服务响应异常（非 JSON）"** | 反向代理没把 `api/` 转发到后端进程。检查 nginx 的 `location /api/` 或子路径前缀转发 |
| **Nginx 返回 502 / 504** | 扫描类接口可能运行数十秒。加大 `proxy_read_timeout`（模板里已设 300s） |
| **首次启动很慢** | 正在拉取全市场日线缓存，约 1~5 分钟，属正常现象；之后每天只补增量 |
| **某个数据源频繁失败** | 到「数据源」页面点「探测」，失败时可临时把该能力锁定到可用源。注意换网络环境后可达性会变 |
| **指数显示成个股** | 不该发生（已有回归测试）。若出现请到「数据源」页面重新探测并检查 `indices` 能力 |
| **策略筛不出东西** | ① 检查扫描结果里的"通过条件"逐条看是哪一条挡住了；② 可能市场环境确实不满足（例如 N 字战法在大盘主跌期会主动停开新仓）；③ 到「策略选股」页放宽阈值 |
| **扫描提示"日线请求已达配额"** | 调大 `quotas.scan_kline_budget`，或把 `universe_size` 设小一些 |
| **企业微信收不到推送** | ① 确认「启用推送」已勾选；② 点「发送测试推送」看返回的错误码（页面会翻译常见错误码）；③ 检查机器人是否还在群里 |
| **容器起来了但访问不了** | 云控制台安全组要放行 `HOST_PORT`；`docker compose ps` 看端口映射是否正确 |
| **移动端表格挤在一起** | 表格是横向滚动的设计；若整体布局异常请强制刷新（HTML 已设 `no-store`） |
| **想彻底离线演示** | 「数据源」页把模式切成 `synthetic`，会使用内置确定性合成行情，页面会显著标注"演示数据" |

## 已知限制

* **行情为免费公开接口**，存在延迟，且不同网络环境下可达性不同；不适合超短线实时决策；
* **复权口径不完全一致**（腾讯/东财/同花顺前复权，新浪日 K 实测不复权），
  除权日附近可能出现跳空；K 线主源已选前复权，且页面显示实际生效源；
* **回测默认次日开盘成交**，与多数原项目"信号日收盘成交"不同，因此回测数字不可直接对比；
* 回测存在**幸存者偏差**（股票池取自当前快照，已退市标的不在样本内）；
* 部分能力（财务、关注度、快讯）为可选，未接入时策略按**中性**处理而非错误扣分；
* 全市场首次建立日线缓存需要数分钟；
* SQLite 为单写者模型，**只支持单实例部署**；
* 北交所部分新股历史数据在免费源上不足 20 根，会被自动跳过而不是产出错误信号。

完整的需求、口径、风险清单与验收标准见 **[docs/requirements.md](docs/requirements.md)**。
